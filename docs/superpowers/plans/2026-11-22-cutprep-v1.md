# CutPrep v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Installierbare Offline-PWA, die Rasterbilder in Cricut-Design-Space-taugliche, nach Farben geschichtete SVGs umwandelt.

**Architecture:** Reiner TypeScript-Kern (`src/core/`, keine DOM-Abhängigkeit, mit Vitest testbar) mit dieser Pipeline: vorverarbeiten → k-means im Lab-Farbraum → Labelkarte glätten und Krümel entfernen → pro Ebene eine Binärmaske (Knockout mit Dilatation, Stapeln oder Einfarbig) → potrace (WASM) pro Maske → mm-skaliertes SVG. Die Pipeline ist in `analyze` (teuer, liefert Palette und Labels) und `render` (billig, läuft bei jeder Palette- oder Regleränderung erneut) geteilt und läuft in einem Web Worker. Die Oberfläche ist Vanilla-TS ohne Framework.

**Tech Stack:** Vite, TypeScript (strict), Vitest, `esm-potrace-wasm` (GPL-2.0), `vite-plugin-pwa` (injectManifest), GitHub Actions → GitHub Pages.

**Spec:** `docs/SPEC.md`

## Global Constraints

- Projektlizenz **GPL-2.0-or-later** (wegen potrace).
- SVG-Ausgabe: nur `<svg>`, `<g>`, `<path fill="#rrggbb" d="…">`; kein `<text>`, `mask`, `filter`, `clipPath`, `transform`, `stroke`, `<image>`, `<style>`.
- `width`/`height` in `mm`, `viewBox="0 0 <wMm> <hMm>"`, Pfadkoordinaten in mm, maximal 3 Nachkommastellen.
- Defaults: Farbanzahl **6** (Bereich 2–8), Zielbreite **20 cm**, Überlappung **0,4 mm**, Mindestteilgröße **1 mm²**, Glättung **0,5** (0–1), Modus **multi**, Stapeln **aus**.
- Arbeitsauflösung: `pxPerMm = 10`, längste Seite höchstens **2400 px** (bei Überschreitung sinkt `pxPerMm` entsprechend).
- Hinweis in der UI, wenn die Zielbreite **21,6 cm** übersteigt (Joy-Xtra-Materialbreite).
- Oberfläche komplett auf Deutsch. Kein Netzwerkzugriff zur Laufzeit außer dem Laden der App selbst.
- Ebenennamen: deutscher Farbname, klein geschrieben, ohne Umlaute im `id` (z. B. `id="gruen"`), Dubletten erhalten `-2`, `-3`; Basis-Ebene beim Stapeln `<name>-basis`.

## Review Focus

1. **Transparente PNGs:** Voll transparente Pixel (alpha < 128) dürfen nicht als Farbe auftauchen, sie gelten automatisch als gelöscht. → Test in Task 3 + Task 4.
2. **Riesige Handyfotos (12 MP+)/kleine Thumbnails (200 px):** Die Arbeitsauflösung wird immer auf die Zielgröße normiert. Es gibt weder Absturz noch Minuten an Rechenzeit (k-means auf Stichprobe ≤ 50 000 Pixel). → Tests in Task 3 + Task 4.
3. **Bild hat weniger Farben als eingestellt** (z. B. schwarz-weißes Logo bei Farbanzahl 6): keine leeren oder doppelten Paletteneinträge, keine leeren Ebenen im SVG. → Test in Task 4 + Task 7.
4. **Alle Farben gelöscht oder bei Einfarbig nichts ausgewählt:** Es wird ein leeres, aber gültiges SVG erzeugt, und die UI zeigt „Keine Ebene ausgewählt“ statt eines Fehlers. → Test in Task 8.
5. **Hintergrund:** Die dominante Randfarbe (≥ 50 % der Randpixel) ist vorab gelöscht, sonst schneidet der Cricut ein Rechteck um das Motiv. → Test in Task 4.

### Task 4: Farbreduktion und Hintergrund

**Files:** Create `src/core/quantize.ts`; Test `test/quantize.test.ts`

**Interfaces:**
- Produces:
  ```ts
  kmeansLab(img: RGBAImage, k: number, opts?: { transparent?: Uint8Array; sampleSize?: number; seed?: number }):
    { palette: RGB[]; labels: Int16Array } // label -1 = transparent
  detectBackground(labels: Int16Array, width: number, height: number): number | null
  ```
- Initialisierung mit k-means++ und deterministischem PRNG (mulberry32, `seed` Default 1). Fitten auf höchstens `sampleSize` (Default 50 000) zufälligen nicht-transparenten Pixeln, höchstens 20 Iterationen, danach Zuordnung aller Pixel. Leere Cluster werden entfernt, Cluster mit deltaE < 3 werden zusammengelegt. Die Palette ist nach Häufigkeit absteigend sortiert, die Labels werden entsprechend neu nummeriert.
- `detectBackground`: Label, das ≥ 50 % der Randpixel stellt (Label -1 zählt nicht), sonst `null`.

- [ ] **Step 1: Tests:** Ein synthetisches 100×100-Bild aus 3 Farbblöcken ergibt bei k=6 genau 3 Paletteneinträge (Review Focus 3). Ein 2400×1800-Bild (Fläche plus Block) läuft in < 2 s (Review Focus 2). Transparente Pixel bekommen Label -1 (Review Focus 1). Zwei Läufe mit gleichem Seed liefern identische Labels. Bei weißem Rand und rotem Kreis in der Mitte liefert `detectBackground` das Weiß-Label (Review Focus 5). Bei drei gleich großen Randfarben liefert es `null`.
- [ ] **Step 2:** FAIL. **Step 3:** Implementieren. **Step 4:** PASS.
- [ ] **Step 5:** Commit `feat(core): k-means und Hintergrunderkennung`.

### Task 6: Ebenenmasken

**Files:** Create `src/core/layers.ts`; Test `test/layers.test.ts`

**Interfaces:**
- Consumes: `PaletteEntry`, `Settings`, `LayerMask`, `rgbToLab`
- Produces:
  ```ts
  resolvePalette(entries: PaletteEntry[]): Map<number, number | null> // Label → Ziel-Label (null = gelöscht), folgt mergedInto-Ketten
  dilate(mask: Uint8Array, w: number, h: number, radiusPx: number): Uint8Array // kreisförmig
  buildLayerMasks(labels: Int16Array, w: number, h: number, entries: PaletteEntry[],
    settings: Settings, pxPerMm: number): LayerMask[]
  ```
- Verhalten von `buildLayerMasks`:
  - **multi + Knockout:** eine Maske je aktivem Ziel-Label (Farbe = `rgb` des Ziel-Eintrags, ggf. umgefärbt), dilatiert um `round(overlapMm * pxPerMm)`. Reihenfolge: größte Fläche zuerst, also unten.
  - **multi + stackOnDarkest:** Das dunkelste aktive Label (kleinstes L*) wird zur Basis = Vereinigung aller aktiven Labels, Name `<farbe>-basis`. Es steht an erster Stelle. Die übrigen Labels kommen undilatiert dazu.
  - **mono:** genau eine Maske = Vereinigung der aktiven Labels mit `monoInclude`, Farbe `[0,0,0]`, Name `schnitt`.
  - Leere Masken werden weggelassen.

- [ ] **Step 1: Tests:** Zwei aneinanderstoßende Flächen im Knockout mit Überlappung 0,4 mm bei 10 px/mm überlappen genau 4 px pro Seite. Beim Stapeln ist die Basis die Vereinigung, die obere Ebene ist nicht dilatiert. Ein gemergtes Label geht in die Zielmaske ein. Ein gelöschtes Label erscheint in keiner Maske. Bei mono ohne Auswahl ist das Ergebnis `[]`.

### Task 8: Pipeline und Worker

**Files:** Create `src/core/pipeline.ts`, `src/worker.ts`; Test `test/pipeline.test.ts`

**Interfaces:**
- Consumes: alles aus Tasks 2–7
- Produces:
  ```ts
  interface Analysis { width: number; height: number; pxPerMm: number; labels: Int16Array; palette: PaletteEntry[] }
  analyze(src: RGBAImage, settings: Settings): Analysis
    // workingSize → resizeBilinear → flattenAlpha → autoLevels → kmeansLab(colorCount)
    // → majorityFilter(round(smoothing*3)) → removeSmallRegions(minPartAreaMm2*pxPerMm²)
    // → Palette: Namen via germanColorName, Hintergrund deleted=true, monoInclude nur für dunkelstes
  render(a: Analysis, palette: PaletteEntry[], settings: Settings, tracer: Tracer):
    Promise<{ svg: string; layers: { id: string; name: string; color: RGB; svg: string }[]; warnings: string[] }>
    // turdsize = ceil(minPartAreaMm2 * pxPerMm²), alphamax = 0.5 + smoothing * 0.8
  ```
- Warnungen (exakter Text): `"Breiter als 21,6 cm – passt nicht auf das Joy-Xtra-Material"`, `"Keine Ebene ausgewählt"`.
- Worker-Nachrichten: `{type:'analyze', image, settings}` → `{type:'analyzed', analysis}`; `{type:'render', palette, settings}` → `{type:'rendered', result}`; Fehler → `{type:'error', message}`. Die Analyse bleibt im Worker gecacht. Eine Änderung von `colorCount`, `smoothing`, `minPartAreaMm2` oder `targetWidthCm` löst eine neue Analyse aus, alles andere nur ein `render`.

- [ ] **Step 1: Tests (mit Fake-Tracer, der pro Maske ein Rechteck aus der Bounding-Box liefert):** Ein synthetisches Bild aus weißem Hintergrund, rotem Kreis und schwarzem Ring ergibt eine Palette, in der Weiß gelöscht ist, und ein SVG mit 2 Gruppen, für das `validateCricutSvg` `[]` liefert. Mit allen Farben gelöscht entsteht ein gültiges SVG ohne Gruppen plus die Warnung „Keine Ebene ausgewählt“ (Review Focus 4). Zielbreite 25 cm liefert die Breiten-Warnung.
